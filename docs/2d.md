# 2D games

Spot's 2D systems use the XY plane with Y up and angles in radians around Z. Entities keep their ordinary
3D transforms; 2D physics preserves their Z position. The renderer uses the public graphics API, and the
Box2D v3.1.1 backend lives entirely in `engine/physics/box2d/`. `SPOT_PHYSICS_2D=BOX2D` selects it independently
of the 3D backend.

## Physics

Start with `BoxCollider2D`, `CircleCollider2D`, `CapsuleCollider2D` or `PolygonCollider2D`, then add a
`Rigidbody2D` to make an entity dynamic. Without one, its colliders form a static body. All active colliders
on an entity share one body, including trigger shapes; triggers do not change its collision response.
Polygon vertices define a convex hull of three to eight points. Capsules stand along Y and include their caps
in their height. Circles use the larger world scale; boxes and polygons scale on each axis. As with 3D physics,
hierarchies that introduce shear cannot be represented exactly.

```cpp
auto& player = scene.CreateEntity("Player");
player.AddComponent<Spot::CapsuleCollider2D>(0.3f, 1.5f);
auto& body = player.AddComponent<Spot::Rigidbody2D>();
body.SetRotationLocked(true);
body.AddImpulse({2.0f, 5.0f});
```

`Scene::GetPhysics2D()` lazily creates a fixed-step scene system. Dynamic bodies write their simulated world
pose back to their entities. Static bodies follow edited transforms; kinematic bodies move toward their authored
poses over a step and push dynamic bodies. Collider/configuration changes rebuild bodies while retaining
velocity. Disabling or removing components and destroying entities updates the next step or query.

Mass, gravity scale, damping, continuous collision, rotation locking and sleeping are configurable on
`Rigidbody2D`. Forces and torque apply during the next step; apply sustained forces from `OnFixedUpdate()`.
Impulses change velocity immediately. Before the world exists, velocities and impulses become starting velocity.
`PhysicsSettings::gravity2D` and the shared layer collision matrix reach scenes through project settings.
All five components are available through the editor's Add Component menu and their serialized inspector fields.

Override `OnCollisionEnter2D`, `OnCollisionStay2D`, `OnCollisionExit2D`, `OnTriggerEnter2D` and `OnTriggerExit2D`
on gameplay components. Events aggregate compound contacts per entity pair; normals point toward the receiving
entity. Stay events run while either body is awake. Exits retain the other entity's id even after its destruction.
Callbacks run after simulation, under the component exception guard, and may edit, query or destroy entities.
Two triggers do not emit events together. These hooks are separate from the 3D hooks.

`Raycast`, `RaycastAll`, `CircleCast`, `OverlapCircle` and rotated `OverlapBox` use the same `QueryFilter` as 3D:
layer mask, trigger inclusion and an entity to ignore. Directions are normalized internally; ray hits are ordered
nearest first. A circle cast starting inside a shape reports distance zero; rays starting inside a shape follow
Box2D's surface-cast convention and do not hit that shape. Queries see collider edits immediately and transform
movement at the next fixed step. Returned collider pointers last only until the components change; retain ids.

For games without scenes, `Physics2D`, `BodyDesc2D`, `Shape2D` and stable `BodyId2D` handles provide the same
simulation, contacts, force and query mechanisms. Output vectors retain capacity. Invalid descriptions are logged
and return `BodyId2D::Invalid`; stale handles are harmless. Simulation and query calls belong to the game thread.

## Sprite sheets and animation

A `.atlas` source describes rectangular regions of an imported texture and named animations. The atlas importer
validates version 1 metadata, unique names, pixel bounds and positive per-frame durations, and cooks the metadata
into a `SpriteAtlas` asset. The texture is still an ordinary texture asset: its id stays stable, and reloading it
also invalidates loaded atlases. Runtime loading needs no source files. Pixel coordinates start at the texture's
top-left. Rotation and packed/trimmed sprites are not part of this format.

In the asset browser, select a texture and use Create > Sprite Atlas. Without a texture selection, it starts from
the first texture in the project. The inspector edits the texture, dimensions, named regions and animation lists;
Apply validates and imports the change with undo, and Revert discards the draft. The dimensions must match the
texture when it is loaded. Add array elements through the ordinary inspector array controls.

`SpriteRenderer` accepts an atlas and frame index in place of its whole-texture rectangle. Color, world size,
ordering and flips keep working. Set its size explicitly; selecting a frame does not resize the entity.
`SpriteAnimator` assigns the atlas and current frame to the renderer on its entity. Choose a named animation,
speed and initial playing state in the inspector, or call `Play("Walk")`. Disabling freezes playback, and pause
and time scaling follow the scene's update time. A non-looping animation stops on its last frame.

```cpp
auto atlas = assets.Load<Spot::SpriteAtlas>("sprites/hero.atlas");
player.AddComponent<Spot::SpriteRenderer>().SetSize({1.0f, 2.0f});
auto& animator = player.AddComponent<Spot::SpriteAnimator>();
animator.SetAtlas(atlas);
animator.Play("Walk");
```

`SpriteAnimationPlayer` offers the same timing without a component, and `SpriteAtlas::GetRegion()` returns the
UV rectangle for code-only renderer calls. Playback allocates nothing while advancing and handles large time
steps by reducing loop time directly. Keep the atlas alive while a player refers to it.

## Tilemaps

Create a Tilemap from the editor's 2D Object menu. It adds `Tilemap` and `TilemapCollider2D` together. Assign an
atlas, set the dimensions and cell size, and fill the definitions list: each definition selects an atlas sprite
and whether that tile is solid. The inspector's scrollable painting grid uses a definition index as its brush;
left drag paints, right drag erases, and Escape cancels. A drag interpolates skipped cells and becomes one undo
step on release. Selection, component and document identities are checked on each operation.

Cells are row-major, with `(0, 0)` at the bottom-left of the entity and `-1` for empty. Maps are bounded to 256
cells on each axis. Resizing preserves cells inside the new bounds. The component saves the grid, definitions,
atlas, order and tint with the scene. Runtime edits use `SetCell()`, `Resize()` or validated `SetData()`.
For code without scenes, `TilemapData` provides the same grid operations and collision generation.

`DrawScene(Renderer2D&, Scene&)` batches tiles with sprites, respecting component order, entity depth and traversal
order. The game renderer and editor viewport use that path too, including maps with no ordinary sprites. The
entity transform moves, scales and rotates the whole grid; occupied cells without an atlas draw the tint color.
The editor can frame, select and outline a map's rectangular bounds. Its painter previews atlas regions.

`TilemapCollider2D` turns solid definitions into compound box shapes on the same entity. Neighboring solid runs
merge horizontally and matching runs merge vertically, while holes and non-solid tiles stay open. Generation
takes linear time in the grid size. Editing tiles rebuilds the compound body at the next physics step or query;
ordinary collision events, filters, trigger mode and queries still work, and hits report the tilemap collider.
Disabling the map removes its generated geometry. Add a `Rigidbody2D` only when the whole map should move as a
body. Collision boxes follow the entity's world scale and rotation just like other 2D colliders.

## Pixel-perfect cameras

On an orthographic `Camera`, enable Pixel Perfect and choose pixels per world unit and a reference resolution.
The renderer uses the largest integer scale fitting that resolution into the actual viewport, with a minimum
of one. Extra viewport pixels reveal more world, and a smaller viewport crops the reference view at scale one.
The option replaces the ordinary orthographic size. It also works on the code-only `Camera2D` and `Camera3D`
through their `pixelPerfect` settings; with `Camera2D`, it replaces the ordinary zoom.

Camera positions and quad edges are snapped for drawing only, including odd-sized viewports. The authored
transforms and simulated positions remain continuous. `Camera2D::ScreenToWorld()` uses the same snapped view
as drawing, so pointer picking stays aligned. Textures use nearest sampling, and the game renderer and editor
viewport skip bloom, FXAA and tonemapping dithering for this camera. Choose Linear tonemapping to preserve source
palette colors; the authored tonemapping operator and grading still apply. UI canvases still use their ordinary screen layout.

```cpp
camera.SetProjection(Spot::CameraProjection::Orthographic);
camera.SetPixelPerfect(true);
camera.SetPixelsPerUnit(16.0f);
camera.SetReferenceResolution({320.0f, 180.0f});
```

Size sprites in source pixels divided by pixels per unit, and choose tile cell sizes on the same grid. Sharp
pixel art assumes axis-aligned quads and an unrotated XY camera; arbitrary rotations and fractional source-pixel
sizes cannot maintain square texels. Perspective cameras ignore this option. Invalid settings fall back to the
ordinary view. Custom rendering must pass the camera to `Renderer2D::Begin()` to select snapping and sampling;
the matrix-only overload keeps ordinary rendering behavior.
